# Roadmap

All resolved issues and completed phases are archived in `docs/CHANGELOG.md`.

## Completed Phases (summary)

- **Phase 1** (v0.2.3): Critical fixes — firmware vitals bugs, sys.exit removal, path traversal, falsy-zero
- **Phase 2** (v0.3.0): Stability & thread safety — concurrency hardening, error telemetry, rate-limiting
- **Phase 3** (v0.3.x): Code quality — refactoring, observability, error standardization, firmware structs
- **Phase 4** (v0.4.0): Firmware v2 — runtime guard rails, CMD_RESET, EVT_DIAG, poll/tick architecture, unit tests

## Aspirational (beyond v0.4)

**Wellness & Engagement**
- **Guided breathing exercises**: Robot leads real-time breathing sessions — breathes (antenna motion) at a target pace, monitors actual BR via radar, adjusts tempo to guide the user down
- **Session journaling / wellness log**: After each interaction, summarize observations (vitals context, mood cues) into a structured log; enables "how was my day" review
- **Circadian awareness**: Use time-of-day + lux patterns + vitals trends to adapt robot personality — calmer in the evening, more energetic in the morning
- **Stress detection heuristic**: Elevated HR + BR + stillness over sustained period flags stress; robot gently offers breathing exercise or topic change (conservative, only when multiple signals align)

**Interaction Quality**
- **Conversation memory across sessions**: Persist conversation summaries (not transcripts) so the robot remembers context between sessions ("you mentioned your knee yesterday")
- **Proactive check-ins**: Robot initiates brief check-ins when it detects presence after absence ("Haven't seen you since this morning — how's your day?"); builds on IdlePolicy presence/absence patterns
- **Emotion-responsive behavior**: Use voice tone analysis + vitals context to modulate robot expressiveness (e.g., dial back jokes when someone sounds stressed and HR is elevated)

**Technical / Platform**
- **Adaptive guard rails**: Firmware learns personalized vitals baselines over time and adjusts thresholds
- **Multi-person vitals**: When target isolation improves in future sensor firmware, support per-person vitals tracking
- **Multi-user profiles**: Per-user vitals baselines and conversation memory for shared-robot households (lux analytics already have `user_id` field)
- **Data export (CSV / Apple Health / FHIR)**: Standard health data export formats for sharing with doctors or health apps
- **Local/offline LLM fallback**: Fall back to a local model for basic conversation + vitals monitoring when OpenAI is unreachable
- **Voice activity detection improvements**: Replace audio threshold approach with a proper VAD model for better turn-taking
- **Over-the-air firmware updates**: Host Python code pushes firmware updates to XIAO over USB
- **Sensor fusion**: Combine mmWave radar with camera vision for more robust person tracking
- **Plugin architecture**: Full external tool/profile marketplace with versioning and dependency management
