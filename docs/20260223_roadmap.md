# Roadmap & Known Issues

## Known Issues

### High Priority

- No timeout on tool dispatch — a hanging tool blocks the entire event loop (openai_realtime.py:567)
- `openai_realtime.py` handler logic now covered via TranscriptHandler/ToolDispatcher/AudioRouter tests, but the streaming loop itself still has low direct coverage
- Race condition in antenna blending: unguarded read-modify-write (moves.py:599-633)
- Session setup exception returns early but connection object may already be set (openai_realtime.py:415-417)

### Medium Priority

- Idle tool call flag (`is_idle_tool_call`) not reset on exception path (openai_realtime.py:538-583)
- Light baseline saved to disk on every single lux sample — excessive I/O (light_orchestrator.py:156)
- Lux extraction key paths in `env_utils.py` may not match `mmWave.py` output structure (env_utils.py:161-185)
- Tool registry runs disk I/O and can `sys.exit(1)` at import time (core_tools.py:286)
- `tools.txt` entries silently skipped if the tool class doesn't exist (core_tools.py:143-264)
- Gradio pinned to dev version `5.50.1.dev1` (pyproject.toml)
- mypy only covers `src/`, not `tests/` (pyproject.toml)
- `requires-python >=3.10` but mypy targets 3.12 — code may use 3.12-only features

### Low Priority

- Unbounded per-hour baseline growth in LightOrchestrator — no pruning over months
- Float precision loss in cost accumulation (openai_realtime.py:43-55)
- Magic numbers in moves.py timing constants without documentation (lines 266-282)
- Dead commented-out code in HeadWobbler (head_wobbler.py:149-157)
- IdlePolicy state machine transitions undocumented — would benefit from state diagram
- BIO state field captured but never used (mmWave.py:440-446)
- Targets truncation flag extracted but never surfaced to user (mmWave.py:349-377)

## Future Vision

### Handler Decomposition (complete)

All major concerns extracted from `_run_realtime_session()` into standalone, testable classes: IdlePolicy, LightOrchestrator, TranscriptHandler, ToolDispatcher, AudioRouter. The event loop is now a ~80-line thin router. See `docs/plans/2026-02-23-decompose-session-design.md`.

### Robustness

- Tool dispatch timeout via `asyncio.wait_for()`
- Protocol version handshake on connection (validate HELLO frame)
- Graceful degradation when mmWave sensor disconnects mid-session

### Testing

- Integration tests for the async streaming loop with mock WebSocket
- Boundary condition tests for bio rate filtering (exact guard-rail values)
- File I/O error tests for LightOrchestrator persistence (corrupted JSON, permissions)

### Sensor Intelligence

- Multi-person tracking: use targets truncation flag, handle >1 target
- Use BIO state field for richer context (e.g., "user was moving during measurement")
